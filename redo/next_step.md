# ขั้นตอนถัดไปสำหรับ Part 2

เริ่มจากชุดอังกฤษ 633 แถวสำหรับติด label และทดสอบ RAG ก่อนขยายไปทั้ง handoff รอบนี้ใช้ tag ตรงตัว `en`, `en;en` และ `en;en;en`

| ชุดข้อมูล | ไฟล์ | จำนวนแถว |
| --- | --- | ---: |
| Linear SVM handoff ของรอบอังกฤษ | [svm_handoff.csv](master/english_only/dataset/svm_handoff.csv) | 6,334 |
| ตัวอย่าง 10% สำหรับติด label | [rag_label_sample_10pct.csv](master/english_only/dataset/rag_label_sample_10pct.csv) | 633 |
| สรุปโควตาของตัวอย่างรายกลุ่ม | [rag_sample_cluster_quotas.csv](master/english_only/dataset/rag_sample_cluster_quotas.csv) | 60 กลุ่ม |

เก็บงานต่อใน [`redo/next_step/`](next_step/README.md) ใช้ `id` จาก CSV เป็นคีย์เชื่อม label ผลของตัวเปรียบเทียบ และผลทดสอบ

## 1. เตรียมกติกาติด label

- ระบุว่าในแต่ละอีเมลต้องหา chunk คู่มือข้อใดบ้างที่เกี่ยวข้อง แล้วคืนชุดรหัส `required_chunk` ตามชื่อฟิลด์ที่ [โค้ด RAG เดิม](../legacy_logistic_regression/part2/RAG/main_RAG.py) ใช้
- ใช้ฐานความรู้และรหัส chunk รุ่นเดียวกันตลอดรอบทดสอบ และระบุในกติกาว่าจะติด label อย่างไรเมื่อมีหลาย chunk เมื่อไม่มี chunk ที่เกี่ยวข้อง หรือเมื่อหลักฐานยังไม่ชัด
- แยกแถวที่จะใช้ปรับกติกาและ prompt ออกจากแถวที่กันไว้เทียบผลรอบ final ตั้งแต่ต้น

## 2. ติด label เป็น batch

- ใช้ **1 subagent ต่อ 1 batch** แนะนำ batch ละ **25 แถว** ทั้งรอบทดลอง รอบติด label ชุด 633 และเมื่อขยายไปยัง handoff เต็ม ชุด 633 แถวจะแบ่งได้ 26 batch โดย batch สุดท้ายมี 8 แถว
- ส่งเฉพาะ `id`, `subject`, `body`, กติกาติด label และเนื้อหาคู่มือที่จำเป็นสำหรับงานใน batch นั้น
- เริ่มจาก batch ทดลอง ให้ส่ง label พร้อมเหตุผลสั้น ๆ ได้เพื่อช่วยทบทวนกรณีที่ตีความต่างกัน ตรวจผล ปรับกติกา แล้วลอง batch ถัดไปจนผู้ทำเห็นว่าพร้อมใช้จริง
- หลังล็อกกติกา ให้เก็บผล final เป็น `id` และ label ตรวจว่าทุก ID ครบและไม่ซ้ำ และรหัส chunk อยู่ในฐานความรู้รุ่นที่ใช้

## 3. เทียบผลกับ Sonnet และทดสอบ RAG

- ใช้ **Claude Sonnet 5.5 Medium** เป็นตัวเปรียบเทียบ ให้ทำบนแถวชุดเดียวกัน ภายใต้กติกาติด label และฐานความรู้ชุดเดียวกัน
- การประเมินรอบ final ให้เทียบ **label เท่านั้น** เช่น เทียบชุด `required_chunk` ตาม `id` โดยไม่นับลำดับของรหัส เหตุผลจากรอบทดลองใช้สำหรับทบทวนกติกา
- ให้ผู้ทำเป็นคนกำหนดว่าจะวัดประสิทธิภาพ RAG อย่างไร ใช้เกณฑ์ใดตัดสิน และผลระดับไหนเหมาะจะขยายไปทั้ง handoff บันทึกวิธีทดสอบและผลไว้ใน `redo/next_step/`
- หลังประเมิน RAG บนชุดตัวอย่างแล้ว ให้ทดสอบการส่งผลค้นคืนไปใช้กับ [Local LLM ของ Part 2](../legacy_logistic_regression/part2/LLM/main_LLM.py) และบันทึกผลตามวิธีที่ผู้ทำเลือก
- ให้จบการติด label และประเมินบน 633 แถวก่อน เมื่อผู้ทำตัดสินว่าพร้อมจึงขยายไปยังแถวที่เหลือใน handoff โดยใช้ ID และ label ที่ตรวจแล้วจากชุดตัวอย่างร่วมด้วย
